# 笔记关联逻辑

## 什么是 Dataview 与 DataviewJS？

实现自动关联信息的代码，部分通过 [`Dataview`](https://github.com/blacksmithgu/obsidian-dataview) 和 DataviewJS 实现。前者有自己的一套查询语法，后者可以加入 JavaScript 代码。两者的区别是：

- **Dataview** 是一个 Obsidian 插件，允许你使用类似 SQL 的查询语言从笔记中提取数据并展示出来。
- **语法简单**：Dataview 查询语法相对简单，适合不熟悉编程的用户，可用于显示特定笔记、任务或其他信息。
- **功能强大**：可以创建动态列表、表格和日历视图，展示基于笔记数据的结果。
- **DataviewJS** 是 Dataview 的扩展，允许使用 JavaScript 编写更复杂的查询和数据处理逻辑。
- **灵活性高**：DataviewJS 提供完整的 JavaScript 编程能力，适合有编程经验的用户。
- **高级功能**：可以进行复杂的数据处理、计算和格式化，甚至结合其他 JavaScript 库。

## 哪里可以修改关联逻辑？

绝大多数关联现在都由 **Bases**（`.base` 文件）承担，修改对应 Base 即可，不需要写代码：

1. 学者笔记的“相关论文”→ `00 - Obsidian/模板/论文检索.base`
2. 机构笔记的“关联学者”→ `00 - Obsidian/模板/学者检索.base`
3. 概念卡的“相关论文 / 相关学者 / 围绕的输出”→ `10 - Cards/概念反查.base`
4. 项目笔记的“参与者 / 相关论文 / 相关书籍”→ `00 - Obsidian/模板/项目素材反查.base`

只有两处仍用 `dataviewjs`，因为 Bases 在结构上无法表达：

1. **概念卡的“相关想法”**——需要按行检索全库带 `#想法` 的句子，而 Bases 只能查询文件级属性。
2. **基金笔记的“交付义务”**——需要跨文件汇总带 `#grant/<slug>` 的 checkbox，而 Bases 看不见笔记内部的任务。

这两处代码块直接写在笔记中，可以就地修改。

## 修改前后的检查

1. 先复制准备修改的 `.base` 文件或笔记，并记录原查询条件；
2. 确认查询使用的字段名与模板实际 frontmatter 一致；
3. 用一个应当命中的样本和一个不应命中的样本验证结果；
4. 修改 DataviewJS 时同时检查空值、数组和单值字段；
5. 验证成功后再应用到正式模板，不要同时改字段生产端与查询端。
