# 笔记导出模板

## 前置条件

- 了解 [Pandoc](https://pandoc.org/) 的[模板系统](https://pandoc.org/MANUAL.html#templates)；
- 有一定 [LaTeX](https://www.latex-project.org/) 基础；
- 如需修改过滤器，了解 [Lua](https://www.lua.org/)；
- 已经让 PaperOut 默认工作流成功生成过一次目标文件。

> [!note] PaperBell 当前导出链
> 正文手稿默认使用 `00 - Obsidian/pandoc/defaults/paperbell.yaml`，LaTeX 模板是 `00 - Obsidian/pandoc/templates/paperbell.latex`，Lua 过滤器位于 `00 - Obsidian/pandoc/filters`。真正生效的组合仍以 PaperOut 当前工作流及其 defaults 文件为准。

因此，定制导出可以从三层入手：[修改 Pandoc 参数](#修改-pandoc-参数)、[修改-latex-模板](#修改-latex-模板)或[修改过滤器](#修改过滤器)。每次只改一层，便于定位编译失败的原因。

## 随包资产与 Pandoc 自带资产

`00 - Obsidian/pandoc` 中的 defaults、templates、filters 和 CSL 是 **PaperBell 随发布包提供的项目资产**。它们不等同于 Pandoc 安装目录中的系统级 data directory，也不表示本机已经安装 Pandoc、LaTeX 引擎或 `pandoc-crossref`。

- **随包资产**：可以直接查看和复制，用于描述 PaperBell 配方；
- **Pandoc/TeX 可执行程序**：需要在本机安装并能被 PaperOut 调用；
- **Pandoc 默认 data directory**：是 Pandoc 自己查找用户级模板等资源的位置，除非工作流明确指向，否则不要与 vault 内的 `00 - Obsidian/pandoc` 混为一谈；
- **资产市场**：用于补缺或安装额外配方/样式，不是 v5.0.1 基础资产的固定安装前置步骤。

## 修改 Pandoc 参数

Pandoc 可以转换 `.pdf`、`.docx` 等格式。导出 PDF 时通常还需要 LaTeX 引擎，因此 PaperBell 以 Pandoc 参数文件组织模板、资源路径、过滤器和参考文献处理。

常见参数包括：

- `--defaults`：选择参数文件。正文默认配方为 `00 - Obsidian/pandoc/defaults/paperbell.yaml`；自定义参数文件也应放在 defaults 目录，并由工作流明确调用。
- `--data-dir`：指定 Pandoc 数据目录。只有当前工作流确实设置该参数时，才会改变模板等资产的查找位置。
- `--resource-path`：设置图片和附件等资源的查找路径，可包含当前手稿目录、vault 附件目录及手稿下的 `img` 或 `imgs`。
- `--template`：选择模板。PaperBell 当前模板文件是 `00 - Obsidian/pandoc/templates/paperbell.latex`；自定义 defaults 应指向你新复制的模板。
- `--reference-section-title`：设置参考文献小节标题。
- `--listings`：启用代码块相关的 LaTeX listings 处理。
- `--number-sections`：控制章节编号。

当前 defaults 目录提供：

- `paperbell.yaml`——正文手稿与补充材料；
- `response-letter.yaml`——返修回复信；
- `cover_letter.yaml`——投稿信；
- `crossref.yaml`——图表和公式交叉引用，供其他预设引入。

## 修改 LaTeX 模板

PaperBell 的 `paperbell.latex` 可追溯到 [Eisvogel](https://github.com/Wandmalfarbe/pandoc-latex-template) 模板并做了中文适配；**Eisvogel 是上游谱系，不是本发布包安装的模板文件名**。

安全做法如下：

1. 在 vault 外备份 `00 - Obsidian/pandoc/templates/paperbell.latex`；
2. 在同一 templates 目录中复制它并使用新的明确名称，例如 `paperbell-custom.latex`；
3. 根据需要修改新模板，不要直接覆盖基线 `paperbell.latex`；
4. 复制 `00 - Obsidian/pandoc/defaults/paperbell.yaml` 为新的 defaults 文件，例如 `paperbell-custom.yaml`；
5. 在新 defaults 的 `template` 配置中，把模板指向 `paperbell-custom.latex`；
6. 在 **PaperOut To-Authors** 中复制现有工作流，让副本调用 `paperbell-custom.yaml`；
7. 用固定测试手稿对照默认输出，检查中文字体、标题、引用、图片、表格和页码。

> [!warning] 模板名与 defaults 必须成对修改
> 只复制 LaTeX 文件但不修改自定义 defaults，PaperOut 仍会使用 `paperbell.latex`；只改原始 `paperbell.yaml`，则更新资产时更难区分本地改动与发布包基线。

## 修改过滤器

`00 - Obsidian/pandoc/filters` 提供导出过程中使用的 Lua 过滤器。大多数来自 [`obsidian-pandoc-filters`](https://github.com/zcysxy/obsidian-pandoc-filters)，其中 `link` 和 `mute` 是 PaperBell 修改或新增的实现。

过滤器的顺序由 defaults 指定，顺序变化可能改变结果：

```yaml
filters:
  - PATH/mute.lua
  - PATH/image.lua
  # 其他过滤器
```

`PATH` 表示实际过滤器目录。复制并定制过滤器后，应让自定义 defaults 指向副本，不要在尚未验证时覆盖所有工作流共用的原文件。

> [!tip] 引用与交叉引用
> `citeproc`、`pandoc-crossref` 及 bibliography/CSL 的配置取决于目标配方；其中某些组件需要额外安装。vault 中存在过滤器或 CSL 文件，不等于相应可执行程序已经可用。

## 最小回归检查

- 默认工作流在修改前后都能继续编译；
- 自定义工作流确实调用新的 defaults 和模板，而不是原始 `paperbell.yaml` / `paperbell.latex`；
- 正文、中文字体、标题层级、图片、表格和代码块正常；
- citation key 能被 bibliography 解析，参考文献样式符合所选 CSL；
- 交叉引用、脚注和 Mermaid 等实际使用的功能均有测试样本；
- 输出文件位置和文件名符合 PaperOut 工作流设置；
- 失败时可以恢复原工作流和随包基线资产。
