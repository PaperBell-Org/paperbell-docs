# 第五部分：高级定制

本部分面向已经跑通 PaperBell 默认工作流，并且确实需要调整笔记结构、关联视图或输出格式的用户。高级定制不是首次使用的必经步骤；如果只是安装、使用或排错，请先返回[快速上手](../02-快速上手/index.md)、[详细教程](../03-详细教程/index.md)或[插件介绍](../04-插件介绍/index.md)。

> [!danger] 先建立可恢复基线
> 模板、字段、Bases 查询和 Pandoc 资产会影响后续生成或更新的文件。修改前请使用独立练习副本，备份原文件并记录插件版本；每次只改一层，验证成功后再继续。

- [ ] 我准备了可重复使用的测试项目、测试文献或测试输出；
- [ ] 我不会直接在唯一一份正式研究资料上试验。

## 按目标选择阅读路线

### 修改 Zotero 文献笔记

```text
先确认 ZotLit 2.1.0-beta.3 与七个 Eta 模板槽位
→ 在 vault 外备份七个 `zt-*.eta.md`
→ 每次只修改一个模板
→ 从真实 Zotero 测试条目新建文献笔记
→ 刷新索引并测试更新，检查属性、批注与引用
```

进入：[ZotLit 模板自定义](01-ZotLit模板自定义.md)

### 修改笔记之间的自动关联

```text
先确认权威字段
→ 判断当前视图由 Bases 还是 DataviewJS 提供
→ 在测试副本中修改查询
→ 用已知样本检查命中与漏检
```

进入：[笔记关联逻辑](02-笔记关联逻辑.md)

### 修改 Word 或 PDF 输出

```text
先让默认 PaperOut 工作流成功编译
→ 复制准备修改的资产
→ 只改 defaults、模板或过滤器中的一层
→ 对照默认输出检查正文、引用、图表和文件位置
```

进入：[笔记导出模板](03-笔记导出模板.md)

> [!important] 以当前 PaperOut 配方为准
> 导出资产会随 PaperOut 和资产市场更新。修改前先在 PaperOut 中确认当前工作流实际使用的 defaults、模板、过滤器与 CSL，不要仅凭旧文件名推断编译链。

## 通用修改原则

1. **先复制，后修改**：把原模板或资产备份到活动目录之外；
2. **一次只改一层**：不要同时修改字段、目录、模板和插件设置；
3. **使用固定测试数据**：修改前后使用同一篇文献、同一个项目或同一份手稿；
4. **检查真实文件**：不能只看插件提示，应核对 Markdown、属性、关联结果和导出文件；
5. **保留回退路径**：确认失败时能够恢复原文件和原设置；
6. **最后再处理正式资料**：测试副本通过后，再小批量应用到正式数据。

## 修改后的最小回归检查

- ZotLit 仍能创建并更新文献笔记，手写内容没有被覆盖；
- Inputs Bell 仍能按字段把文件归入正确目录；
- 学者、机构、概念与项目视图仍能返回预期结果；
- Project Manager 与 Task Genius 仍能识别测试项目和任务；
- PaperOut 仍能实际生成并打开 Word 或 PDF；
- 修改前已有的 Markdown 文件和附件仍然可读。

如果任一项失败，先恢复最近一次修改，不要继续叠加新的定制。
