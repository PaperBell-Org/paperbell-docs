# 跑通第一个科研闭环

## 本次练习要完成什么

本页只要求每个工作流成功执行一次。所有步骤都围绕测试项目 `quickstart`，方便检查关系并在练习后统一清理。

```mermaid
flowchart LR
    A[测试项目] --> B[测试文献]
    B --> C[日记与项目任务]
    C --> D[Web Clipper 采集]
    D --> E[学者与机构]
    E --> F[科研工作流概念卡]
    F --> G[PaperOut 测试稿]
    G --> H[Pandoc 首次导出]
```

> [!important] 时间从这里开始
> 软件下载、首次索引、版本兼容处理和 Pandoc 工具链安装不计入本页时间。环境已经通过前四页检查后，建议预留 **60–90 分钟**。

## 开始前准备

- [ ] PaperBell 练习库已经备份；
- [ ] Zotero 正在运行，并有一篇带父条目和 PDF 的测试文献；
- [ ] Web Clipper 已连接当前练习库，通用网页剪藏已经成功，`Scholar clipper` 模板已经导入；
- [ ] 命令面板可以找到项目、ZotLit、Daily Notes、Thino、QuickAdd 和 PaperOut 入口；
- [ ] Pandoc、XeLaTeX、pandoc-crossref 和当前手稿配方均已通过 PaperOut 检查；
- [ ] 本次统一使用项目 ID `quickstart`；
- [ ] 没有配置 AI 时，我会使用手工概念卡或学者档案备选路径，但仍会完成实际导出。

## 时间分配

| 时间 | 任务 |
| --- | --- |
| 0–8 分钟 | 创建测试项目和项目任务 |
| 8–18 分钟 | 从 Zotero 导入一篇文献 |
| 18–25 分钟 | 创建日记并写入一条项目任务 |
| 25–40 分钟 | 用 Web Clipper 建立学者与机构档案 |
| 40–50 分钟 | 建立或关联概念卡 |
| 50–90 分钟 | 创建 PaperOut 写作项目并完成首次导出 |

## 第一步：创建测试科研项目

1. 打开命令面板，执行 **PaperBell Project Manager: 新建科研项目**；
2. 显示名填写 `PaperBell 快速上手`；
3. `acronym` 填写 `quickstart`；
4. 其他字段使用测试值或保持默认；
5. 创建后打开项目主页，确认它位于：

   ```text
   40 - Projects/PaperBell 快速上手/
   ```

6. 在项目主页添加一条里程碑：

   ```markdown
   - [ ] 完成 PaperBell 快速上手 #milestone #project/quickstart
   ```

7. 打开 Task Genius 的 Projects 视图，确认 `quickstart` 下可以看到该任务。

验收重点是项目主页中的 `acronym: quickstart`、`project/index` 标签和 `project/quickstart` 标签。完整说明见[管理科研项目](../03-详细教程/02-管理科研项目.md)。

## 第二步：从 Zotero 导入一篇文献

1. 在浏览器中打开测试论文详情页，使用 Zotero Connector 保存父条目和 PDF；
2. 在 Zotero PDF 阅读器中添加至少一条高亮，最好再写一条评论；
3. 确认条目已有稳定 citation key；
4. 回到 Obsidian，在 ZotLit 中执行 `Refresh index`；
5. 使用 ZotLit Companion 的创建命令，或从 Obsidian 端 ZotLit 快速切换器选择该条目；
6. 等待文献笔记出现在：

   ```text
   20 - Inputs/Zotero/<citekey>.md
   ```

   

打开文件，至少确认：

- 文件名与 `citekey` 一致；
- 作者、标题和来源信息存在；
- 正文包含 ZotLit 管理区域；
- `## Annotations` 中能看到测试高亮；
- Inputs Bell 没有误删字段或把文献移到错误目录。

如果导入失败，不要手工伪造一篇文献来宣告闭环完成；先按照[Zotero文献导入 Obsidian](../03-详细教程/03-Zotero文献导入Obsidian.md)定位是 Connector、Zotero、Companion、ZotLit 还是 Inputs Bell 出现问题。

## 第三步：写入日常记录和项目任务

1. 打开命令面板，执行 **Daily notes: Open today's daily note**；
2. 确认日记位于 `30 - Metadata/DailyNote`，并包含 `## 概览` 与 `## 日程`；
3. 打开 Thino 快速输入框；
4. 切换为 Task 类型，输入：

   ```text
   继续整理快速上手测试文献 #project/quickstart
   ```

5. 保存后回到当天日记，确认 `## 日程` 下出现一条 `- [ ]` 任务；
6. 回到 Task Genius 的 `quickstart` 项目，确认这条日记任务也能被识别。

这一步验证 Thino 只是捕获入口，数据仍写入普通 Markdown 日记。完整用法见[日常记录](../03-详细教程/04-日常记录.md)。

## 第四步：建立学者与机构档案

### 路径 A：使用 Web Clipper 完成自动采集

这是完整体验的推荐路径：

1. 选择测试文献的第一作者，并打开该学者的一页公开个人主页；
2. 点击浏览器工具栏中的 **Obsidian Web Clipper**，不要误点 Zotero Connector；
3. 选择 `Scholar clipper` 模板；
4. 在预览中核对 `name`、`website`、`institute`、`keywords` 和 `tags`；
5. 如果模板调用 Interpreter，只使用自己信任的模型服务，不要提交登录后页面或未公开个人信息；
6. 点击 **Add to Obsidian**，允许浏览器打开当前 PaperBell 练习库；
7. 先观察文件是否进入 `20 - Inputs`，随后全库搜索学者姓名，确认 Inputs Bell 已将它移动到：

   ```text
   30 - Metadata/Scholars
   ```

8. 检查 `30 - Metadata/Institutes` 中是否已经创建或复用对应机构档案；
9. 打开学者档案，确认 `aliases` 覆盖测试文献中的作者写法，并人工核对机构与研究关键词。

> [!note] 保存后入口目录为空不一定是失败
> Inputs Bell 可能在你查看前就完成移动。先按学者姓名、来源 URL 或 `scholar` 标签全库搜索，不要连续重复剪藏。

### 路径 B：没有合适网页或尚未配置 Interpreter

1. 执行 `QuickAdd: 添加学者`；
2. 使用作者规范姓名作为文件名，填写常见别名、主页、机构和少量关键词；
3. 执行 `QuickAdd: 添加机构`，使用正式机构名称建立档案；
4. 确认学者和机构分别位于 `30 - Metadata/Scholars` 与 `30 - Metadata/Institutes`。

手动路径可以让后续闭环继续进行，但它没有验收 Web Clipper。完成快速上手后，仍应找一页公开学者主页返回路径 A 测试一次。模板、Interpreter 与 Inputs Bell 规则的完整说明见[追踪学者和组织](../03-详细教程/05-追踪学者和组织.md)。

## 第五步：建立或关联概念卡

统一使用测试概念：`科研工作流`。

### 路径 A：Cards Wrangler 1.0.2 已具备可用 AI



1. 打开刚导入的文献笔记；
2. 执行 Cards Wrangler 的 `Ingest current note`；
3. 检查候选概念，保留或补充 `科研工作流`；
4. 在确认界面检查回写内容后应用结果；
5. 确认概念卡已经创建或复用，并且文献的 `keywords` 已更新。

### 路径 B：尚未配置 AI

1. 执行 `QuickAdd: 添加术语`；
2. 名称填写 `科研工作流`；
3. 按模板填写一句简短定义；
4. 把 `科研工作流` 写入文献笔记的 `keywords`，并按需在项目或输出中链接 `[[科研工作流]]`；
5. 确认文件位于 `10 - Cards/Concepts`。

无论选择哪条路径，打开概念卡后，应分别确认：文献与学者通过 `keywords` 匹配，项目与输出通过指向概念卡的链接反查。自动提取、批量处理和概念治理见[概念卡使用场景](../03-详细教程/06-概念卡使用场景.md)。

## 第六步：创建 PaperOut 写作项目

### 1. 创建测试写作项目

1. 在文件列表中右键 `50 - Outputs/Longform`，选择 **新建 PaperBell 论文项目…**；也可以在命令面板运行同名命令；
2. 项目标题填写 `PaperBell 快速上手测试稿`；在“所属 PaperBell 项目”中选择 `quickstart`；
3. 保留默认勾选的 Main Manuscript；补充材料、回复信和投稿信按需勾选；
4. 创建后确认项目中包含 Main Manuscript、元数据和参考文献等起步文件；
5. 打开 Main Manuscript 的一个场景，写入一小段测试文字，并链接 `[[科研工作流]]` 或测试文献；
6. 确认内容保存于 `50 - Outputs/Longform` 下的 PaperOut 项目中。

### 2. 执行首次导出

1. 打开 PaperOut 编译面板；
2. 选择 Main Manuscript 及其当前 `PaperBell Manuscript` 工作流；
3. 再次确认系统工具与当前配方没有缺失提示；
4. 执行一次测试编译并等待流水线结束；
5. 在 PaperOut 配置的输出位置找到生成的 PDF；如果你明确改用了 DOCX 配方，也可以用生成的 Word 文件验收；
6. 打开导出文件，确认至少能看到测试标题、刚才写入的正文，以及已经加入的概念或文献内容；
7. 回到 PaperOut 查看本次编译记录，确认不是只生成了中间 Markdown。

> [!warning] 创建项目不等于完成导出
> 如果最终只有 PaperOut 项目、场景或拼接后的 Markdown，而没有 Word 或 PDF，本次完整闭环尚未完成。回到[安装基础软件](02-安装基础软件.md)与[下载并打开 PaperBell](03-下载并打开PaperBell.md)，分别检查系统工具和 vault 内资产。

首次只要求成功生成一种目标格式，不要求同时配置所有投稿模板。完整导出能力见 [PaperOut To-Authors 使用指南](../03-详细教程/07-PaperOut%20To-Authors%20使用指南.md)。

## 最终闭环检查

| 检查项   | 成功标准                                    |
| ----- | --------------------------------------- |
| 项目    | `quickstart` 项目存在，Task Genius 能看到项目任务   |
| 文献    | ZotLit 文献笔记存在，元数据与批注可以核对                |
| 日记    | Thino 任务写入当天日记，并带 `#project/quickstart` |
| 网页采集  | Web Clipper 已连接正确 vault，通用网页剪藏已成功       |
| 学者与机构 | 两份档案存在，姓名与机构关系一致                        |
| 概念    | `科研工作流` 概念卡存在，并至少连接一个测试对象               |
| 输出    | PaperOut 写作项目和 Main Manuscript 已创建      |
| 编译    | Pandoc 工作流成功结束，并实际生成、打开至少一份 Word 或 PDF  |

任何一项失败，都先停在该步骤查看最后成功产生的文件，不要继续累积后续错误。

## 清理测试数据

练习完成后，可以搜索 `quickstart`、`PaperBell 快速上手` 和 `科研工作流`，逐项确认后删除测试项目、测试日记内容、测试档案、概念卡和 PaperOut 测试稿。

删除前注意：

- 不要误删原本就需要保留的真实 Zotero 文献和 PDF；
- 删除项目主页前先检查 `#project/quickstart` 任务；
- 删除概念卡前先检查反向链接；
- PaperOut 项目应整组确认，不要只删除其中一个场景；
- 同时确认是否要删除 Web Clipper 测试剪藏和 PaperOut 生成的 Word/PDF。
