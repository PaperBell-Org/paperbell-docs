# PaperBell 主插件

PaperBell 主插件是整个 PaperBell 插件体系的宿主和授权中心。它现在只负责两件事：

| 职责 | 作用 |
| --- | --- |
| 激活主插件和子插件 | 验证 PaperBell 账户或注册 ID，并处理子插件的授权请求 |
| 保存大模型 API | 统一保存 AI 提供方、请求协议、Base URL、模型和 API 密钥，供获得授权的子插件使用 |

文献导入、项目管理、概念卡整理等具体功能由各个子插件完成，不应继续归到 PaperBell 主插件名下。

## 安装与入口

**[PaperBell 官网与激活入口](https://paperbell.cn)**

PaperBell 库已经包含主插件。进入“设置 → 第三方插件”，确认 **PaperBell** 已启用，然后打开“设置 → PaperBell”。

建议先启用 PaperBell 主插件，再启用需要使用账户授权或 AI 配置的子插件。

> [!note] 激活不等于安装
> PaperBell 只能为已经安装并启用的子插件提供授权。它不会代替 Obsidian 安装插件，也不会自动打开第三方插件开关。

## 一、激活 PaperBell

进入“设置 → PaperBell → 许可证”，可以使用两种方式完成激活。

### 方法一：账户登录

1. 点击 **登录**；
2. 在浏览器中完成 PaperBell 账户授权；
3. 返回 Obsidian；
4. 确认设置页显示“已登录”或已激活账户。

需要更换账户时，使用 **切换账户**，不要直接复制其他设备的本地配置文件。

### 方法二：注册 ID

1. 从 PaperBell 官网获取注册 ID；
2. 在 **🎓 注册 ID** 中粘贴；
3. 点击 **验证**；
4. 确认出现“激活码已验证”，并检查许可证是否仍在有效期内。

注册 ID 属于账户凭据，不要写入笔记、教程截图或公开仓库。

## 二、激活和授权子插件

子插件启动后，会向 PaperBell 主插件注册。当它第一次请求账户状态、共享配置、AI 调用或受保护资源时，PaperBell 会显示授权窗口。

授权窗口会列出：

- 请求授权的插件名称和 ID；
- 申请访问的能力；
- **允许**或拒绝选项。

只有确认插件名称和用途正确时才允许。授权完成后，可在 PaperBell 设置中的 **已授权应用** 查看授权范围；不再使用某个子插件时，可以点击 **撤销**。

常见授权能力包括：

| 能力 | 含义 |
| --- | --- |
| `config` | 读取语言和模型等共享配置，不包含 API 密钥 |
| `activation` | 检查 PaperBell 账户是否已经激活 |
| `llm-invoke` | 由 PaperBell 使用当前 AI 配置代子插件调用模型 |
| `llm-credentials` | 允许子插件读取当前模型配置和密钥，并自行发起请求 |
| `download-ticket` | 获取受保护子插件或资源的下载授权 |

`llm-credentials` 的权限高于普通配置读取。只有明确知道该子插件为什么需要直接访问密钥时才允许。

## 三、保存大模型 API

进入“设置 → PaperBell → AI”。PaperBell 支持内置的 OpenAI、Anthropic，以及自定义的 OpenAI 兼容提供方。

### 1. 选择或新建提供方

在 **当前提供方** 中选择要使用的服务。如果使用代理、国产模型或其他 OpenAI 兼容服务，点击 **新建提供方**。

不同提供方可以分别保存自己的模型、Base URL 和 API 密钥。切换提供方时，子插件会使用当前选中的配置。

### 2. 填写请求协议

| 请求协议 | 适用情况 |
| --- | --- |
| OpenAI 兼容 | OpenAI，以及大多数兼容 OpenAI 请求格式的代理和模型服务 |
| Anthropic | 使用 Anthropic 原生请求格式的服务 |

协议决定请求体和鉴权头格式。不能只根据模型名称猜测，应以模型服务商的 API 文档为准。

### 3. 填写三个核心字段

```text
API 密钥：模型服务商提供的密钥
Base URL：API 服务地址
模型：服务商实际支持的模型 ID
```

模型名称必须填写服务商真正接受的 ID。显示名称、产品宣传名称和 API 模型 ID 不一定相同。

### 4. 测试连接

点击 **测试连接**。预期结果是“连接成功”。如果失败，依次检查：

1. API 密钥是否完整，前后是否包含空格；
2. Base URL 是否正确，是否重复添加路径；
3. 请求协议是否与服务商一致；
4. 模型 ID 是否真实存在；
5. 账户是否有余额、额度或模型权限；
6. 当前网络能否访问该服务。

## 四、API 密钥怎样保存

PaperBell 会优先使用 Obsidian 的钥匙串功能保存 API 密钥，密钥不会写入插件的 `data.json`。`data.json` 只保存提供方、Base URL、模型等非密钥配置。

因此：

- 不要把 API 密钥再复制到 Markdown 笔记；
- 不要在截图中展示完整密钥；
- 不要把密钥写入模板、脚本或同步仓库；
- 更换或泄露密钥后，应到服务商后台撤销旧密钥，再在 PaperBell 中填写新密钥；
- 每个提供方使用独立密钥，删除提供方前先确认不再使用。

## 五、主插件与子插件的边界

```text
PaperBell 主插件
├── 验证账户与许可证
├── 管理子插件授权
└── 保存并提供 AI 配置

子插件
├── 执行具体工作流
├── 按需请求激活状态
└── 经用户授权后使用 AI
```

如果文献导入、项目任务或模板渲染出现问题，应先检查对应子插件，而不是把所有问题都归到 PaperBell 主插件。只有下面两类问题优先检查主插件：

- 账户、许可证或子插件授权失败；
- 子插件提示缺少 API 密钥、模型或 Base URL。

## 六、最小验收

1. 打开“PaperBell → 许可证”，确认账户或注册 ID 已激活；
2. 打开“PaperBell → AI”，选择当前提供方；
3. 检查协议、API 密钥、Base URL 和模型；
4. 点击“测试连接”，确认连接成功；
5. 打开一个需要 PaperBell 授权的子插件；
6. 核对授权窗口中的插件名称和权限，再选择允许；
7. 回到“已授权应用”，确认可以查看并撤销该授权。

## 常见问题

> [!faq]- PaperBell 已激活，为什么子插件仍不能使用？
> 激活不能代替安装和启用。先确认子插件已安装、已打开；再检查它的授权请求是否被拒绝或撤销。必要时重启 Obsidian，让子插件重新注册。

> [!faq]- 为什么设置页不显示已经填写的 API 密钥？
> 这是正常的安全设计。密钥保存在 Obsidian 钥匙串中，输入框不会回显完整内容；需要更换时直接输入新值覆盖。

> [!faq]- 为什么子插件还会单独询问 AI 权限？
> 保存密钥不代表所有子插件都能读取。PaperBell 会按插件和权限范围单独请求授权，避免密钥被默认开放给所有插件。

> [!faq]- “测试连接”成功，为什么 AI 功能仍然失败？
> 再检查子插件是否获得 `llm-invoke` 或 `llm-credentials` 权限、模型是否支持该请求，以及服务商账户是否有足够额度。

> [!faq]- 撤销授权会删除子插件吗？
> 不会。撤销只移除子插件访问 PaperBell 能力的权限，不会卸载插件或删除其笔记数据。
