# 追踪学者和组织

PaperBell 不需要为每一位论文作者建立档案。更合适的做法是：只追踪与你的研究方向高度相关、经常出现，或需要长期关注的学者与机构。

完成后，三类信息分别位于：

| 内容 | 位置 |
| --- | --- |
| 学者档案 | `30 - Metadata/Scholars` |
| 机构档案 | `30 - Metadata/Institutes` |
| Zotero 文献笔记 | `20 - Inputs/Zotero` |

本工作流分为两条路径：

- **自动创建**：适合已有公开学者主页、希望快速采集资料的情况；
- **手动创建**：适合没有合适网页、资料需要人工核对，或只想录入少量核心字段的情况。

## 一、开始前确认四个插件

| 插件 | 在本工作流中的职责 |
| --- | --- |
| **[Web Clipper](../04-插件介绍/01-Obsidian外插件/05-Web-Clipper.md)** | 从学者主页提取姓名、机构、主页和研究方向等信息 |
| **[Inputs Bell](../04-插件介绍/02-PaperBell工作流核心插件/02-Inputs-Bell.md)** | 处理自动采集的笔记，匹配机构并把文件归位 |
| **[QuickAdd](../04-插件介绍/02-PaperBell工作流核心插件/09-QuickAdd.md)** | 提供“添加学者”和“添加机构”两个手动入口 |
| **[Templater](../04-插件介绍/02-PaperBell工作流核心插件/08-Templater.md)** | 执行手动模板中的提问并生成统一字段 |

先确认四个插件均已安装，并按各自介绍页完成 PaperBell 的特殊配置。

## 二、自动创建

自动路径适合 Google Scholar、ORCID、ResearchGate、OpenAlex 等公开学者页面。

```text
学者主页
→ Web Clipper 的 Scholar clipper 模板
→ 20 - Inputs
→ Inputs Bell 后处理
→ 30 - Metadata/Scholars
→ 必要时在 30 - Metadata/Institutes 创建机构档案
```

### 1. 完成一次性设置

1. 在 Web Clipper 中导入 PaperBell 的 `Scholar clipper` 模板。
2. 确认模板的保存位置为 `20 - Inputs`，并会写入 `scholar` 标签。
3. 在 Inputs Bell 中启用以下脚本：

```yaml
enabledScripts:
  - normalize-frontmatter
  - localize-images
  - link-institution
  - move-by-frontmatter
```
{>>这里的顺序和示例库 `paper-in-bell/data.json` 里存的数组顺序不一样（那边是 normalize → localize → **move-by-frontmatter** → link-institution），但脚本文件是按数字前缀命名的：`10-normalize` / `20-localize` / `40-link-institution` / `90-move-by-frontmatter`，所以**实际执行顺序应该是这一页写的这个**，配置数组只是存储顺序。而且逻辑上也只能是这个顺序——link-institution 必须赶在 move 之前跑完，否则学者笔记已经被移出 `20 - Inputs`，机构就关联不上了。建议在这里补一句「顺序由脚本文件名的数字前缀决定，设置里的排列不影响执行」，省得读者去设置里对不上号<<}

4. 在 `move-by-frontmatter` 的规则中，{~~将下面一行放在~>确认下面一行存在，且位于~~}{>>示例库里这条规则**已经内置好了**，位置也正在 `tag:clip` 之前，读者不需要自己加。写成「添加」会让人以为发布包缺东西，跑去设置里找、发现已经有了，反而困惑。02-快速上手/03-下载并打开PaperBell.md:98 那边写的就是「确认存在」，口径对齐一下<<} `tag:clip` 之前：

```text
tag:scholar => /30 - Metadata/Scholars
```

> [!important]
> PaperBell 当前的 Web Clipper 模板同时写入 `scholar` 和 `clippings`。Inputs Bell 按**第一条命中的规则**归类；如果没有提前加入 `tag:scholar`，文件会被 `tag:clip` 规则移到 `20 - Inputs/Clippings`。

### 2. 抓取学者主页

1. 打开学者的公开主页。
2. 启动 Web Clipper，选择 `Scholar clipper`。
3. 检查预览中的姓名、别名、主页、机构和研究关键词。
4. 确认保存，等待笔记进入 `20 - Inputs`。

不同网站的页面结构并不统一，因此该模板会使用 Web Clipper Interpreter 辅助提取。涉及个人信息或未公开材料时，不要发送给外部模型；模型调用也可能产生费用并延长处理时间。

### 3. 等待 Inputs Bell 处理

Inputs Bell 会对新笔记执行字段归一化，并读取 `institute` 字段。匹配到可靠的 ROR 机构记录时，它会使用：

```text
00 - Obsidian/模板/机构模板pro.md
```

在 `30 - Metadata/Institutes` 中创建或复用机构档案，随后把学者笔记移入 `30 - Metadata/Scholars`。

ROR 用于消除机构名称歧义，但自动匹配仍可能遇到同名机构、院系名称或历史名称。首次创建后请人工核对机构名称、官网与 `ror_id`。

### 4. 验收自动创建结果

- 学者文件位于 `30 - Metadata/Scholars`；
- `name` 与文件名一致；
- `aliases` 包含论文中常见的姓名写法；
- `institute` 使用机构名称，而不是院系、实验室或地址；
- 机构文件位于 `30 - Metadata/Institutes`；
- 学者页中的“相关论文”能够显示已有 Zotero 文献。

## 三、手动创建

手动路径不经过 `20 - Inputs`，而是直接在目标目录中生成档案。

```text
QuickAdd 命令
→ 学者模板.md / 机构模板.md
→ Templater 执行字段提问
→ 30 - Metadata/Scholars 或 30 - Metadata/Institutes
```

### 1. 手动创建学者

1. 打开命令面板，执行 `QuickAdd: 添加学者`。
2. 输入学者姓名作为文件名。
3. 按 Templater 提示填写别名、主页、机构和研究关键词；不确定的字段可以留空。
4. 检查生成的学者档案。

这里最重要的是 `aliases`。`论文检索.base` 通过作者名与当前学者的别名匹配论文，因此应同时保留论文中常见的英文写法、缩写或中文名。

### 2. 手动创建机构

1. 打开命令面板，执行 `QuickAdd: 添加机构`。
2. 使用机构的正式名称作为文件名。
3. 按提示填写简称、别名、官网、**经纬度（Maps插件使用）** 和 Logo。
4. 检查“Affiliated Scholars”是否能够检索到已关联的学者。

手动创建机构时使用 `00 - Obsidian/模板/机构模板.md`；自动创建机构使用 `机构模板pro.md`。两者用途不同，不要互换。

## 四、字段约定

| 字段 | 用途 | 建议 |
| --- | --- | --- |
| `name` | 档案的规范名称 | 与文件名保持一致 |
| `aliases` | 连接论文作者名或机构别名 | 保留常见拼写与缩写 |
| `institute` | 学者当前所属机构 | 使用机构名，不使用 `institution` |
| `website` | 官方主页 | 优先使用机构或个人官网 |
| `keywords` | 学者研究方向 | 使用少量、稳定的主题词 |
| `following_date` | 开始关注的日期 | 由模板自动写入 |

## 五、最小排错顺序

| 现象 | 先检查 |
| --- | --- |
| Clipper 保存后找不到文件 | Web Clipper 的保存库与路径是否为 `20 - Inputs` |
| 学者笔记进入了 Clippings | `tag:scholar` 规则是否存在且位于 `tag:clip` 之前 |
| 没有创建机构档案 | `institute` 是否填写、`link-institution` 是否启用、ROR 是否成功匹配 |
| QuickAdd 没有“添加学者/机构” | 两个 Choice 是否启用为命令 |
| 模板代码原样留在文件里 | Templater 是否启用，模板目录与新建文件触发是否正确 |
| 学者页没有关联论文 | `aliases` 是否覆盖 Zotero 文献中的作者写法 |
