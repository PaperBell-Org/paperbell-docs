# 日常记录

日常记录的目的不是每天写一篇完整文章，而是在不中断工作的情况下，保存灵感、决定、问题和下一步行动。PaperBell 使用 Daily Notes 管理按日期组织的日记文件，再用 Thino 快速把内容写回当天日记。

本工作流解决四个问题：

1. 怎样创建结构统一的当天日记；
2. 怎样用 Thino 随手记录闪念；
3. 怎样把闪念连接到项目、概念和任务；
4. 怎样通过回顾把内容送往 CIMPO 的其他层。

## 一、开始前确认两个组件

| 组件 | 在本工作流中的职责 |
| --- | --- |
| **[Daily Notes 日记模块](../04-插件介绍/02-PaperBell工作流核心插件/06-Daily-Notes.md)** | 创建当天日记，统一文件名、目录与模板 |
| **[Thino](../04-插件介绍/02-PaperBell工作流核心插件/07-Thino.md)** | 快速捕获闪念，并把内容写入当天日记的 `## 日程` |

Daily Notes 是 Obsidian 核心插件，Thino 是社区插件。两者必须共用同一套日记目录和日期格式，不能各自创建一份日记。

## 二、确认唯一的日记配置

进入“设置 → Daily notes”，确认：

| 设置 | PaperBell 当前值 |
| --- | --- |
| Date format | `YYYY年MM月DD日` |
| New file location | `30 - Metadata/DailyNote` |
| Template file location | `00 - Obsidian/模板/每日日记模板.md` |

> [!warning] 目录是单数 `DailyNote`
> 不要改成 `DailyNotes`。Thino、QuickAdd、Templater 和部分查询都依赖 `30 - Metadata/DailyNote`。

在 Thino 中应选择使用 **Daily** 的默认配置，并关闭独立日记设置。这样 Thino 会跟随上表，而不会在其他位置创建第二份当天日记。

## 三、创建当天日记

### 方法一：使用 Daily Notes 命令

打开命令面板，运行：

**Daily notes: Open today's daily note**

当天文件不存在时，Daily Notes 会自动创建：

```text
30 - Metadata/DailyNote/YYYY年MM月DD日.md
```

### 方法二：使用 Calendar 插件

如果已经启用 **Calendar** 插件，也可以直接在侧边栏日历中点击当天日期：

1. 打开 Calendar 日历视图；
2. 点击今天或需要补记的日期；
3. 如果对应日记尚不存在，在提示窗口中确认创建；
4. Calendar 会按照 Daily Notes 的目录、日期格式和模板打开或创建日记。

Calendar 只是更直观的日期入口，仍然共用 Daily Notes 的配置，不应另外设置一套日记目录。它还适合补写过去某一天的记录。

### 检查模板结果

日记应包含：

```yaml
---
date: YYYY-MM-DD
tags: DailyNote
week: YYYY-WW
---
```

正文至少包含：

```markdown
## 概览

## 日程
```

模板还会生成前一天、后一天和本周记录链接。日期计算依赖文件名，因此不要随意把日记重命名成其他格式。

## 四、用 Thino 捕获第一条闪念

打开 Thino 可以使用侧边栏入口，也可以在命令面板运行：

- **Thino: Show daily thino**：打开日常记录视图；
- **Thino: Show thino editor**：打开独立的快速输入框。

输入一条带唯一测试词的内容，例如：

```text
测试 Thino 是否正确写入今天的日记
```

保存后打开当天日记，预期在 `## 日程` 下看到：

```markdown
- HH:mm 测试 Thino 是否正确写入今天的日记
```

这说明 Thino 只是快速入口，真正的数据仍然保存在普通 Markdown 日记中。

## 五、四种常用记录方式

### 1. 普通闪念

不确定归属时先直接记录：

```markdown
- 09:20 访谈对象对风险的理解可能受到最近一次灾害经历影响
```

捕获时不必停下来建立完整分类。先保留现场，回顾时再整理。

### 2. 关联科研项目

如果内容明确属于某个项目，添加与项目 `acronym` 一致的标签：

```markdown
- 10:15 需要重新核对访谈抽样标准 #project/flood-risk
```

项目主页和相关查询会通过 `#project/<acronym>` 找到这条记录。标签的大小写、连字符和拼写必须与项目主页一致。

### 3. 关联概念和想法

如果内容是一条值得以后回顾的研究想法，加入 `#想法`，并尽量连接已有概念卡：

```markdown
- 11:30 关于[[风险感知]]和灾害记忆之间的关系又有一个想法 #想法
```

- `#想法` 表示这是一条待回顾的研究灵感；
- `[[风险感知]]` 建立与概念卡的明确链接；
- 如果概念卡有别名，后续查询也更容易覆盖不同写法。

不要为了每条闪念立即创建新概念卡。只有当一个概念反复出现，并且已经能用自己的话解释时，再进入概念卡工作流。

### 4. 记录可以执行的任务

普通 Thino 默认保存为列表项。如果内容已经是明确行动，可以切换到 Task 类型，生成：

```markdown
- [ ] 14:20 整理访谈提纲 #project/flood-risk
```

这时：

- Thino 负责快速写入；
- `- [ ]` 让 **[Task Genius](../04-插件介绍/02-PaperBell工作流核心插件/04-Task-Genius.md)** 将其识别为任务；
- `#project/flood-risk` 把任务归到对应项目。

只有关键阶段成果才额外添加 `#milestone`：

```markdown
- [ ] 16:00 提交研究方案 #milestone #project/flood-risk
```

## 六、用“每日总结”补充当天概览

**[QuickAdd](../04-插件介绍/02-PaperBell工作流核心插件/09-QuickAdd.md)** 还提供 **每日总结** 命令。运行后输入一句话，会把内容写到当天日记的 `## 概览`：

```markdown
- 总结:: 完成访谈提纲，仍需核对样本排除标准。
```

它适合一天结束时概括真正推进的事情，不用于代替 Thino 的即时捕获，也不用于保存完整会议记录。

## 七、回顾并把内容送往其他层

Thino 更适合作为收件箱，而不是最终归档位置。捕获时追求快速，整理工作放到每日或每周回顾。

| 记录成熟后的性质 | 应流向 |
| --- | --- |
| 值得长期保存的外部来源 | `20 - Inputs` |
| 可以稳定解释的跨项目知识 | `10 - Cards` |
| 明确目标、任务或里程碑 | `40 - Projects`，并保留项目标签 |
| 已经承担论点或方法说明的文字 | `50 - Outputs` |
| 只用于解释当天背景的过程记录 | 继续保留在 DailyNote |

### 每日收尾

- [ ] 写一句当天总结；
- [ ] 给明确行动补上任务语法；
- [ ] 给项目内容补 `#project/<acronym>`；
- [ ] 保留下一次恢复工作时的第一步。

### 每周回顾

- [ ] 处理仍未解决的问题；
- [ ] 检查没有项目标签的任务；
- [ ] 找出反复出现、值得进入概念卡的主题；
- [ ] 把成熟段落转入输出草稿；
- [ ] 将已经处理完的 Thino 条目归档。

> [!note] Thino 归档不等于删除 Markdown 原文
> 归档主要用于清理 Thino 的活动列表。源日记中的记录通常仍然存在，并附带归档标记，因此项目标签、概念链接和研究过程仍可追溯。

## 八、完成一次最小测试

不要分别测试两个组件，请完成一次端到端测试：

1. 用 Daily Notes 创建当天日记；
2. 确认文件名、目录、YAML 和两个固定标题正确；
3. 用 Thino 保存普通闪念：

   ```text
   测试普通闪念 #想法
   ```

4. 再用 Task 类型保存：

   ```text
   测试项目任务 #project/demo
   ```

5. 检查两条内容是否都进入当天日记的 `## 日程`；
6. 确认第二条是 `- [ ]` 任务，并能在 Task Genius 的 `Projects → demo` 中看到；
7. 归档第一条 Thino，确认活动列表已整理，同时原日记仍可追溯。

## 常见问题

> [!faq]- Thino 为什么创建了另一份当天日记？
> 检查 Thino 是否选择 **Daily** 配置，并关闭 **Use independent settings**。同时核对 Daily Notes 的日期格式和目录。

> [!faq]- Thino 内容为什么没有进入“日程”？
> 检查 Thino 的 **Insert after heading** 是否精确填写为 `## 日程`，并确认模板中存在完全相同的二级标题。

> [!faq]- 为什么 Thino 中的行动没有出现在 Task Genius？
> 普通 List 只是 `- HH:mm` 列表项。请切换为 Task 类型，确保源 Markdown 是 `- [ ]`，再补充项目标签。

> [!faq]- 为什么项目主页找不到这条日记记录？
> 检查记录是否包含与项目 `acronym` 完全一致的 `#project/<acronym>`。

> [!faq]- 所有闪念都要加标签吗？
> 不需要。捕获时优先保存上下文；只给明确属于项目、概念或待回顾想法的内容添加标签和链接。
