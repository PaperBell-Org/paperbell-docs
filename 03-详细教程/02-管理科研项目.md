# 管理科研项目

在 PaperBell 中，项目不是一条待办，也不是一篇正在写的论文，而是一个需要持续协调资料、任务与产出的研究单元。项目主页统一放在 `40 - Projects`，并用一个稳定的项目 ID 把散落在不同笔记中的任务连接起来。

本工作流只解决三个核心问题：

1. 怎样新建一个科研项目；
2. 怎样给项目添加任务；
3. Task Genius 怎样识别这些任务，并把它们归到正确项目。

## 一、开始前确认两个插件

| 插件 | 在本工作流中的职责 |
| --- | --- |
| **[Project Manager](../04-插件介绍/02-PaperBell工作流核心插件/03-Project-Manager.md)** | 创建和编辑项目主页，维护项目 ID，并统计项目里程碑 |
| **[Task Genius](../04-插件介绍/02-PaperBell工作流核心插件/04-Task-Genius.md)** | 索引全库 Markdown 任务，按项目标签汇总、筛选和更新任务 |

第一次使用前，在 Project Manager 设置中确认：

```text
项目根目录：40 - Projects
输出根目录：50 - Outputs
资助目录：30 - Metadata/Grants
项目模板：00 - Obsidian/模板/项目模板.md
项目标签前缀：project/
里程碑标签：milestone
```

在“设置 → Task Genius”中确认：**Index & Sources → Enable Indexer** 和 **Views → Enable Task Genius Views** 已开启，**Projects → Enable project features** 保持关闭。PaperBell 当前不依赖“按文件夹自动判断项目”，而是使用明确的 `#project/<项目ID>` 标签建立关系。

## 二、用 Project Manager 新建项目

### 1. 运行创建命令

打开 Obsidian 命令面板，运行：

**PaperBell Project Manager: 新建科研项目**

### 2. 填写项目信息

创建表单中的字段很多，但第一次测试只需要重点确认以下内容：

| 字段              | 作用          | 示例                      |
| --------------- | ----------- | ----------------------- |
| 显示名             | 项目文件夹和主页的名称 | 洪水风险传播研究                |
| `acronym`       | 项目的稳定、唯一 ID | `flood-risk`            |
| `long_name`     | 项目完整名称      | 城市洪水风险传播机制研究            |
| `type`          | 项目类型        | 研究                      |
| `stage`         | 当前阶段        | `探索`、`进行`、`追踪` 或 `完成` |
| `start` / `end` | 项目起止时间      | `2026-08-01`            |
| `priority`      | 项目优先级       | `high`、`medium` 或 `low` |

`acronym` 会进入项目标签，因此应满足三个条件：**唯一、稳定、便于输入**。**建议以字母开头，只使用字母、数字、连字符或下划线**，例如：

```text
paperbell
flood-risk
R01_omics
```

不要把经常变化的阶段、年份或显示名称直接当作项目 ID。

### 3. 检查创建结果

创建成功后，Project Manager 会生成：

```text
40 - Projects/
└── 洪水风险传播研究/
    └── 洪水风险传播研究.md
```

> [!important] 创建完成后需要自己放入项目图片
> Project Manager 只会在 `banner` 字段中写入图片路径，不会自动创建或复制图片。项目创建完成后，请自己把封面图片放入刚生成的项目文件夹，并确保**实际图片名称与创建时生成的 `banner` 路径完全一致**，包括扩展名。
>
> 例如创建结果是：
>
> ```yaml
> banner: 40 - Projects/洪水风险传播研究/cover.jpg
> ```
>
> 就需要把图片保存为：
>
> ```text
> 40 - Projects/洪水风险传播研究/cover.jpg
> ```
>
> 如果使用的图片名是 `封面.png`，就必须把 YAML 同步改为对应路径；否则项目卡片会显示破图。

项目主页的 YAML 应包含两个关键标签：

```yaml
tags:
  - project/index
  - project/flood-risk
acronym: flood-risk
stage: 进行
```

- `project/index` 让项目进入 PaperBell 的项目列表；
- `project/flood-risk` 是该项目的唯一标签；
- `acronym: flood-risk` 是之后添加任务时要重复使用的项目 ID。

> [!warning] 不要只手动修改 `acronym`
> 项目 ID 可能已经出现在任务、笔记和输出文件中。需要改名时，先打开该项目主页，再运行 **PaperBell Project Manager: 编辑项目**，并检查旧标签是否已经同步更新。这个命令不是常驻选项，只有当前文件被插件识别为项目主页时才会显示。

## 三、先理解任务的识别规则

一条任务要经过两层识别：

```text
- [ ] 整理访谈提纲 #project/flood-risk
  └─┬─┘             └──────────┬──────────┘
   任务语法             项目归属标签
```

1. `- [ ]` 让 Task Genius 把这一行识别为 Markdown 任务；
2. `#project/flood-risk` 让 Task Genius 把任务归入 `flood-risk` 项目。

因此，下面只是普通文本，不会成为任务：

```markdown
整理访谈提纲 #project/flood-risk
```

下面虽然是任务，但没有明确关联项目：

```markdown
- [ ] 整理访谈提纲
```

PaperBell 当前没有启用 Task Genius 的增强型文件级项目识别，所以**即使任务写在 `40 - Projects` 的项目主页里，也建议在每一条项目任务上写完整的 `#project/<acronym>`**。这样任务移到日记、会议记录或其他笔记后，项目关系仍然不会丢失。

## 四、在项目主页添加里程碑

打开刚创建的项目主页，在 `## 🙋 Milestones` 下添加：

```markdown
- [ ] 完成研究方案预注册 #milestone #project/flood-risk 📅 2026-09-01
- [/] 完成第一轮数据收集 #milestone #project/flood-risk
- [x] 冻结分析脚本 #milestone #project/flood-risk
```

这里的两个标签职责不同：

| 标签 | 作用 |
| --- | --- |
| `#project/flood-risk` | 告诉 Task Genius：任务属于哪个项目 |
| `#milestone` | 告诉 Project Manager：这条任务要计入项目里程碑进度 |

普通行动任务不需要 `#milestone`：

```markdown
- [ ] 给合作者发送会议纪要 #project/flood-risk
```

只有可以验证项目关键进展的任务，例如“提交预注册”“完成数据冻结”“提交内部预审”，才适合作为里程碑。

## 五、用 Task Genius 添加项目任务

项目任务不必全部写在项目主页。只要保留相同的项目标签，它们可以出现在日记、会议记录或任何普通 Markdown 文件中。

### 方法一：直接在任意笔记中输入

```markdown
- [ ] 阅读审稿意见 #project/flood-risk
- [ ] 修改方法部分 #project/flood-risk 📅 2026-08-10
```

### 方法二：使用 Task Genius 快速捕获

1. 运行 Task Genius 的快速捕获命令；
2. 输入任务内容；
3. 在同一行加入项目标签；
4. 保存。

例如输入：

```text
整理访谈提纲 #project/flood-risk
```

PaperBell 当前把快速捕获任务写入当天日记，即 `30 - Metadata/DailyNote`。任务虽然不在项目文件夹中，但 Task Genius 会根据 `#project/flood-risk` 把它归入同一项目。

### 方法三：在 Task Genius 中编辑已有任务

打开 Task Genius 任务视图，找到任务后使用内联编辑器补充 Project 或标签。保存后，源 Markdown 也会同步变化。为了与 PaperBell 的项目主页和 Bases 保持一致，最终结果仍应使用：

```text
#project/<acronym>
```

## 六、检查 Task Genius 是否已经识别

完成一条任务后：

1. 打开 **Task Genius View**；
2. 在项目相关视图中选择项目 ID，例如 `flood-risk`；
3. 检查项目主页和日记中的任务是否同时出现；
4. 在 Task Genius 中勾选一条任务，再回到源文件确认 Markdown 状态已经更新。



Task Genius 的项目列表来自已经索引到的任务，而不是 Project Manager 预先建立的一份静态名单。因此，一个刚创建但还没有项目任务的项目，可能暂时不会出现在 Task Genius 的 Projects 视图中。添加第一条带 `#project/<acronym>` 的任务后再检查。

当前常用状态如下：

| Markdown | 含义 |
| --- | --- |
| `- [ ]` | 未开始 |
| `- [/]` 或 `- [>]` | 进行中 |
| `- [?]` | 计划中 |
| `- [x]` 或 `- [X]` | 已完成 |
| `- [-]` | 已放弃或取消 |

Project Manager 的里程碑进度只统计带 `#milestone` 的任务：`[x]` / `[X]` 计为完成，`[-]` 从统计中排除，其余状态仍视为未完成。

## 七、完成一次最小测试

请用一个测试项目完整走一遍，不要把“创建项目”和“测试任务”拆成两次验收：

1. 运行 **新建科研项目**，建立 `demo` 项目；
2. 在项目主页添加：

   ```markdown
   - [ ] 完成测试里程碑 #milestone #project/demo
   ```

3. 用 Task Genius 快速捕获添加：

   ```text
   整理测试资料 #project/demo
   ```

4. 打开 Task Genius 的 **Projects → demo**；
5. 确认两条任务都出现；
6. 完成里程碑，并确认项目卡片进度发生变化。

## 八、项目与任务的 Bases

| 文件 | 当前路径 | 内置视图 | 用途 |
| --- | --- | --- | --- |
| `00. 项目列表.base` | `40 - Projects/00. 项目列表.base` | `项目卡片`、`项目概览`、`详细列表`、`进行中`、`已完成`、`项目产出`、`甘特图` | 以项目主页为主，展示阶段、封面、里程碑、交付物和资助等信息 |
| `01. 任务总览.base` | `00 - Obsidian/模板/01. 任务总览.base` | `按笔记`、`按项目`、`甘特图` | 汇总带 `#project/<acronym>` 的文件与其中任务 |

这些不是只能使用 Obsidian 标准表格的静态文件：`项目卡片` 是 Project Manager 的自定义 Base 视图，`按项目` 和 `甘特图` 使用 Task Genius 自定义 Base 视图。项目主页通过 `project/index` 进入项目列表；普通笔记和任务则通过 `#project/<acronym>` 归属项目。只有带 `#milestone` 的 Markdown 待办才进入 Project Manager 的里程碑统计，`[-]` 被排除，`[x]` / `[X]` 计为完成。



项目主页负责定义“这是什么项目”，Task Genius 负责回答“这个项目现在有哪些任务”。两者通过稳定的 `acronym` 与 `#project/<acronym>` 连接。

## 常见问题

> [!faq]- 为什么项目已经创建，却没有出现在 Task Genius 的 Projects 里？
> Task Genius 的项目列表由已索引任务生成。先添加一条标准 Markdown 任务，并写上与 `acronym` 完全一致的 `#project/<acronym>`。

> [!faq]- 任务写在项目主页里，为什么仍然没有归入项目？
> 只有文件位置并不够。PaperBell 当前不依赖文件级项目识别，请给任务行明确添加 `#project/<acronym>`。

> [!faq]- 写了 `#milestone`，为什么 Task Genius 仍不知道它属于哪个项目？
> `#milestone` 只表示它是里程碑，不表示项目归属。还必须添加 `#project/<acronym>`。

> [!faq]- 为什么普通任务没有进入项目卡片的里程碑进度？
> 这是正常的。Task Genius 会管理所有项目任务；Project Manager 的项目进度只统计带 `#milestone` 的关键任务。

> [!faq]- 修改项目 ID 后出现了两个项目怎么办？
> 搜索旧的 `#project/<acronym>`，统一替换为新标签。以后优先通过 Project Manager 的编辑命令修改项目，而不是只改 YAML。
